## 1. 任务原文与交付目标

**面试题：02｜自然语言智能选股与策略解释器。** 官方要求在 24 小时编程题限制内，设计可操作的 Web 产品：将投资者模糊的自然语言（如「经营改善、估值合理、走势相对稳定」）转成**用户可检查、可修改、可执行**的数据条件，基于真实股票数据返回候选结果，并解释每只股票为何入选、为何排除、修改条件有什么影响。

**官方必交**：

1. 实际可访问、可交互的 **Web URL**（本地 `localhost` 不满足最终公网交付）。
2. 源代码仓库、完整 README（环境变量、运行方式、产品/数据/AI 边界、未做事项）。
3. AI 使用与验证记录（AI 如何辅助，人工发现并修正什么）。
4. 测试说明：主链路、数据缺失/异常、接口失败、极端输入和合规边界。

可选：60–180 秒产品演示视频。金融数据优先官方扶摇 API / iFinD MCP，不提交凭证或受限数据，不提供必涨预测、保收益或直接买卖建议。所有关键结论有来源、时间、单位、计算口径；缺失数据不能静默补零。上述要求优先级高于初期产品方案中的各种可选建议。

**产品定位**：StockLens · AI 智能选股工作台。目标用户是能用日常语言说出选股偏好、但不熟悉财务指标或量化表达式的个人投资者。核心价值不是“AI 推荐股票”，而是**把自然语言翻译为透明规则，用户确认后交给可验证的确定性引擎执行**。

### 产品必须遵守的工作流

`自然语言 → AI 识别用户真正提出的维度及歧义 → 用户补充/修改阈值与启用条件 → Python 基于同一金融数据快照筛选 → 入选/排除/数据不足及逐项证据 → 修改条件并对比变化`

**职责边界**：
- **LLM**：仅解析自然语言、提取结构化规则、提示歧义/未支持条件、说明代理指标；不直接决定股票入选，不生成财务数值，不承诺投资收益。
- **用户**：控制实际启用的条件、阈值、AI 提议值是否采纳，承担最终筛选策略确认。
- **确定性 Python 引擎**：输入参数 + 已采集真实数据，执行稳定规则，逐项返回 PASS / FAIL / UNKNOWN 和中文事实原因。
- **扶摇 API**：股票代码、估值、财报指标、历史价格等真实数据及来源信息；LLM 不能替代。

## 4. 金融数据：实际成功的扶摇 API 接入

### 通用约定

- Base URL：`https://fuyao.aicubes.cn`
- 鉴权请求头：`X-api-key: <secret>`。
- `thscode` 必须带后缀 `.SH` / `.SZ` 等，例如 `600519.SH`、`000001.SZ`。
- 响应信封：`{"code":0,"message":"success","request_id":"...","data":...}`。**不能只检查 HTTP 200，必须检查 `code`**。
- 时间戳为毫秒 Unix 时间；金融数据业务时区：`Asia/Shanghai`。
- 空值 `null` 与无记录必须保持缺失状态，不当作零。
- 动态限流：HTTP 429 或业务 `code=4001`；合理节流/退避，不高并发暴力重试。

### 已实测成功的四类接口

| 数据用途 | GET 路径 / 参数 | 已验证的响应与约束 |
|---|---|---|
| 沪深 300 股票池 | `/api/a-share-index/constituents/ths-stock-list?thscode=000300.SH` | `code=0`，当时返回 300 只股票，含 `thscode`、`ticker`、`name` |
| 估值快照 | `/api/a-share/valuations/snapshot?thscodes=600519.SH,000001.SZ` | `code=0`，`data.item[].pe_ttm`、`pe_mrq`、`pb_mrq`、`ps_ttm`、`pcf_ttm`；每次最多 100 个输入 token |
| 财务能力指标 | `/api/a-share/financials/indicators?thscode=600519.SH&report=2026-3` | `code=0`；`data.abilities[].indicators[]` 含 `index_id` 和字符串形式的 `value`，单股票/报告期调用 |
| 日 K 线批量 | `/api/a-share/prices/historical-batch?thscodes=...&interval=1d&start=<ms>&end=<ms>&adjust=forward` | `code=0`；单次最多 10 只；`data.item[]` 按标的分组；每条 K 线有 `date_ms`、`close_price` 等 |

**财务指标的重要历史经验：** 对于 **归母净利润同比**，本地真实调用时曾出现 `index_id=calculate_parent_holder_net_profit_yoy_growth_ratio`；营收同比曾出现 `calculate_operating_income_yoy_growth_ratio`，ROE 曾出现 `index_weighted_avg_roe`。而上传的聚合文档在某个版本的表里列出了 `net_profit_yoy_growth_ratio` 等名称，注意**归母口径与一般净利润口径并非一回事**。请检查当前 `collect_data.py` 的实际解析字段、真实返回样例和最新文档，**不要因为文档字段名相似就擅自替换为错误的财务口径**。

金融数据百分比 `value="24.47"` 表示 `24.47%`，不是 `0.2447%`。真实返回 `data.abilities[]`，不是假想的 `data.item[]`。`request_id` 必须与数据一起保留用于溯源。

### 指标的严格口径

| 产品用户名称 | 内部字段 | 计算/判定 |
|---|---|---|
| 估值水平 | `pe_max` 对 `pe_ttm` | **`0 < PE TTM <= pe_max`**；负值或零值不能被视为低估值。PE 低不等于必然便宜；当前只支持绝对 PE 上限，不支持「同行业前 10% 低估值」 |
| 盈利增长 | `profit_min` 对 `parent_net_profit_growth_pct` | `实际归母净利润同比增长率 >= profit_min`，百分数原值；报告期如 `2026-3`，并非「连续多个季度增长」 |
| 近期波动 | `vol_max` 对 `volatility_20d_pct` | `实际近 20 日收益率样本标准差 <= vol_max`；用最近 **21 个交易日的收盘价**计算 20 个日收益率（前复权），结果乘 100 表示百分数，**未年化**；低波动不等于上涨或低风险 |

三个指标是为了 24 小时 MVP 建立跨估值/增长/价格行为的确定性闭环，**不是经过回测认证的最佳三因子策略**。PE 20/30、利润增长 10、波动率 2.5 都不是金融意义上的统一「好股票标准」。尤其 AI 生成的阈值不能被写成经过市场统计验证的结论。

### 缺失值三态逻辑

每项条件：`PASS` / `FAIL` / `UNKNOWN`。
- 任一已启用条件 `FAIL` → 股票 `EXCLUDED`，即使另一些条件 `UNKNOWN`；
- 全部已启用条件 `PASS` → `SELECTED`；
- 没有 `FAIL` 且至少一个 `UNKNOWN` → `INSUFFICIENT_DATA`。

未启用的指标**不参与**上述计算，也不应强行在结果详情中产生失败/未知判断。数据请求失败、数据缺失、旧数据不能默默用 0 或 AI 估值代替。

**注意**：PowerShell 5.1 早期直接输出 JSON 中的中文股票名曾乱码；可用 `Invoke-WebRequest` 获取原始响应字节，再用 `[Text.Encoding]::UTF8.GetString($response.RawContentStream.ToArray()) | ConvertFrom-Json` 正确解码。生产 Python `requests` 的 UTF-8 JSON 路径一般无需这个手工步骤。

```json

  "questions": ["你希望市盈率（PE TTM）最高不超过多少倍？"],
  "unsupported": [],
  "interpretation": "用户想筛选估值较低的股票，暂用正市盈率上限作为代理指标。",
  "model": "gpt-4o-mini"
}
```

该 JSON **是预期语义示例，不是声称本地每次 AI 都会返回完全相同文案**。

规则：
- `active_metrics` 只能包含用户真实提出的可支持条件，允许 1/2/3 项；不能为了凑三个指标加无关条件。
- 未指定阈值 → 对应 `parameters` 为 `null`，`sources` 为 `missing`，提示确认；不编造 20 / 30 / 2.5。
- 用户明确说数值（如 PE 低于 20 倍） → `sources=user`，提取对应数字。
- 只有用户要求 AI 提议时才允许 `sources=suggested`；前端需显式确认才生效。
- 未启用维度保持 `null`，不要对它提问。
- 超出支持能力的条件（PB、ROE、行业、连续 3 年增长、指定涨跌趋势、市场分位数、OR/NOT 等）写到 `unsupported`，不应**偷偷忽略后仍执行**。
- 无可执行条件 → 返回澄清/不支持信息，禁止空条件全选。
- 不把“低股价”认作“低估值”，不把“营收增长”认作“归母净利增长”，不把“走势稳定”认作必然上涨。

### 筛选示例

```json
{ "pe_max": 20, "profit_min": null, "vol_max": null }
```

表示**仅 PE 筛选**。至少一个有效数字阈值，不支持三个都 `null`。默认逻辑 `AND`。`ScreenParams` 用 Pydantic v2，禁止未声明字段，范围：PE `>0` 且 `<=100000`，利润增长 `[-10000,10000]`，波动率 `[0,1000]`。

### 修改前后对比

```json
{
  "before": { "pe_max": 20, "profit_min": null, "vol_max": null },
  "after":  { "pe_max": 30, "profit_min": 10, "vol_max": null }
}
```

两个版本必须同一数据快照；后端会标出 `newly_selected`、`no_longer_selected`、`still_selected`。前端修改阈值后无需重新调用 LLM，但必须再次执行 Python 筛选。

### v0.4 具体代码机制

- `intent_parser.py`: 官方 OpenAI Chat Completions `response_format: json_object`、`temperature:0`，然后 `normalize_intent()` 做字段白名单、数值范围、缺失参数、来源和 unsupported 校验。**temperature=0 不是绝对确定性**，应准备多条语义测试用例。
- `screen_engine.py`: `build_strategy()` 忽略 `null`、仅构建活跃条件；`execute_screen()` 计算三态和逐项原因。
- `app.py`: 加载 `.env`，CORS 当前允许 `http://localhost:5173` / `http://127.0.0.1:5173`，默认自动选取最新修改的 `stock_snapshot_*.json`，`POST /api/compare` 读取**同一份**快照后各筛选一次。
- **部署时需重设**前端 `VITE_API_BASE_URL` 与后端 CORS 允许域名，不可把硬编码 localhost 当公网部署完成。

来自项目中的「前端设计」讨论及后续截图反馈：采用**金融专业、克制、精密编辑式界面（Precision Editorial UI）**，参考苹果网站的信息层级和金融工作台气质，不使用夸张科技蓝紫渐变、霓虹发光、泛滥装饰、重阴影或无意义的数据图表。

红色上涨、绿色下跌是当前中文版金融行情语义；**不能将涨跌颜色直接用于筛选通过/不通过的全部场景**，避免语义混淆。控件主色统一深海蓝，背景暖灰白，状态信息有层次但不过度鲜艳。响应式布局须兼顾桌面与窄屏。

### 主要页面结构

1. 导航 / 数据状态 + 三步流程进度；
2. 自然语言大输入区、示例查询、AI 解析；
3. 若解析成功，再显示动态筛选条件（1–3 张卡片，而不是固定三张）；
4. 卡片标题：**估值水平 / 盈利增长 / 近期波动**，次级说明：PE TTM / 归母净利同比 / 20 日波动率；
5. 每张卡片标题旁 **ⓘ 信息按钮**。点击后悬浮解释，支持点外部关闭或 Esc，**悬浮层不参与卡片高度**，展开一张不能牵动旁边卡片；
6. 原先卡片底部「这个指标是什么意思？」折叠区域**已明确要求删除**，不要重新添加；
7. 数值输入保留加减/上下调节能力和清晰单位；来源标记区分“用户描述 / AI 建议待确认 / 待填阈值 / 手动调整”；
8. 条件可增删；目前多个条件采用 AND；点击确认执行后，**全宽结果区**出现，未执行前**不显示巨大空白结果面板**；
9. 结果具备选中/排除/数据不足统计、状态筛选、股票搜索与排序；点击股票在右侧**抽屉**展示逐项条件、报告期/时点、来源请求 ID（技术追踪字段默认折叠）；
10. 修改条件再次筛选，展示同一快照上的新增/移除/仍符合股票。

**版式注意**：用户已反复指出过“左右强烈不对称”“卡片展开联动拉高左右卡片”“说明条占据太大高度”“专业术语不解释”“输入框原生微调箭头丢失”。此前做过对应修正；将其作为回归测试项，尽量不要反复引入。

**关键源文件**：`frontend/src/App.tsx` 一体包含组件图标、数据类型、状态、表格、抽屉、分析流程；`App.css` 样式较多。未来可拆组件，但应先保持功能和 CSS class 稳定，不要为了“代码整洁”一次性重写造成新回归。

### v0.4 前端状态逻辑（根据已生成代码）

`query / analyzedQuery / intent / activeMetrics / draft / touched / accepted / screen / lastParams / comparison / selectedCode / filter / stockSearch / openHelp` 等由 React state 管理。

- `analyze()` 调用 `/api/interpret` 后重置上一轮筛选、对比、抽屉，保留当次解析出来的启用规则。
- 修改用户描述后需要重新解析，否则禁止拿旧解析结果执行新文本。
- `validateDraft()` 只验证启用条件；对 `suggested` 数值要求用户点击确认或亲自修改。
- `runScreen()` 调 `/api/screen`，若与上次参数不同，调 `/api/compare`。结果中的列与证据应根据**已执行**而非**尚未执行**的规则集生成。
- 股票源信息包含 request IDs / 报告期；不显示 API Key。

**待调试逻辑请先查这里**：如果用户觉得“AI 分析没有输出”、“卡片源标记不正确”、“条件虽然增删却影响筛选”、“结果表格与本次条件不一致”或“编辑后旧结果显示不当”，先沿输入→解析 JSON→React state→提交 JSON→筛选引擎→结果映射链路逐项定位，而不是直接猜测模型理解能力不足。

### v0.4 当前已知设计约束（非已确认 bug）

1. 仅三类可执行指标；当前不支持跨行业估值可比性与行业分位数筛选。
2. 只有用户给出或确认阈值后执行；模糊词是澄清点，不能因为用户没写数字就自行填充默认。
3. 未支持条件会阻止整个筛选（例如「找 PE < 20 的银行股」中的银行行业未实现）；可能影响用户体验，但这是防止悄悄漏掉用户要求的**有意保护策略**。如需改进，应明确展示“可支持部分 + 未支持部分”，并由用户显式选择是否忽略，而非自动省略。

5. 缺失/过期处理以现有实现为准；例如保留数据报告期，不代表自动做了完整的新鲜度/冲突校验。
6. 24 小时时限下，不应盲目做全量大而全的 Agent 系统；优先解决真实主链路问题与最终交付要求。

## 8. 交给 Codex 的任务顺序与验收标准

### P0｜首先让用户复现当前问题

**最新用户状态：v0.4 已测试，用户表示“还是有点问题”，准备在 Codex 中详细描述。**

Codex 开始后先确认：用户输入的原话、在哪一步出现、页面实际显示、预期行为、是否收到 HTTP 错误、此时 3 个接口请求/响应、所用快照及版本。能够直接检查代码、Network 请求和本地运行日志就不要让用户重复手动转述。**在未拿到复现证据时不要假定特定原因。**

推荐排查流程：

1. 读取真实 `C:\StockLens` 文件、`package.json`、`.env` 变量名（不输出值）及快照结构，确定本地是哪个版本、变更是否完整。
2. 在不泄露凭证前提下运行现有 Python 单测、前端构建；先修构建和路径错误。
3. 根据用户给出的**输入→AI 原始 JSON→标准化 JSON→UI 启用规则/阈值→POST /api/screen 参数→Python 规则→UI 结果**逐段找差异。
4. 用失败场景增加回归测试（单测/路由层、必要时前端交互）；再做最小代码修复。
5. 让用户在本地重新验收修复的场景；避免未经允许修改其它界面布局。

### P0｜最低限度语义验收矩阵

| 用户原话 | 期望启用条件 | 期望交互 |
|---|---|---|
| 我想找一个市场估值偏低的股票 | `pe_max` | 数值为空，解释用 PE TTM 作为代理，**仅**追问 PE 上限 |
| 找市盈率低于20倍的股票 | `pe_max=20` | 一张卡，能够确认后执行，不需要利润/波动条件 |
| 找市盈率低于30倍、归母净利润同比增长超过10%的股票 | `pe_max=30` + `profit_min=10` | 只出现两张卡，以 AND 筛选 |
| 找利润同比增长超过10%的股票 | `profit_min=10`（需确认是否归母净利口径） | 不添加估值或波动；不应偷换成营收增长 |
| 找最近走势比较稳定的股票 | `vol_max` | 阈值无数值，解释它测量历史收益率波动而非上涨趋势 |
| 找 PE 小于10倍、同时大于30倍的股票 | 条件冲突 | 不得悄悄选择其中一个或错误执行；需要冲突识别和清晰反馈 |
| 找市净率低于1倍的银行股 | 当前不支持 | 显示 PB 与行业范围未支持，不得默默改成 PE |
| 推荐明天必涨的股票 | 无可执行规则 | 不做收益承诺，明确拒绝确定性预测并说明合法用途 |

> 最后一条冲突语句的支持程度应由 Codex 实测判断。旧方案要求冲突检测，但 v0.4 的 parser 主要依赖 LLM 提取+白名单，**不要把完整冲突解析能力视为已验收实现**。

### P0｜筛选引擎单元测试

- PE = 负数/零/阈值边界/空值；利润增长为负、零、正；波动率精确边界。
- 单指标、双指标、三指标；`null` 一定表示**不启用**，不是 `0`。
- 任一 FAIL 优先排除；其余 UNKNOWN 应判数据不足。
- 非法字段、NaN、无穷、超范围、空条件及非法 JSON 拒绝执行。
- `/api/compare` 在同一个快照上变更阈值、增加/删除条件得到正确新增/移出列表。
- 不把结果名为“AI 推荐”、不出现伪造来源/实时价格/预测。

### P1｜产品改进与正式交付

- 先依据用户反馈解决认知和交互漏洞；必要时改进冲突识别、澄清流程，支持“一句自然语言→一个可执行规则”的单条件体验。
- 适度增加取样到 50（如果 API 权限/速度允许），**采用请求节流、分组、部分失败保留与新鲜度提示**；不要一开始盲目抓取完整 300 只造成限流。
- 实现轻量策略保存（如 JSON/SQLite/localStorage；说明隐私与环境限制）或符合题目“保存/回测/监控中至少一种”的路径。当前已有**条件对比**，但题目明确希望有“继续比较、保存、回测或转监控任务”的后续能力，评估是否仅对比已足够并据此补强。
- 部署可访问前后端、CORS、`VITE_API_BASE_URL`、环境变量、持久数据/授权；不能暴露密钥。
- 整理 README、AI 使用与人工纠错记录、测试说明，若有余力制作 60–180 秒真实操作演示。
