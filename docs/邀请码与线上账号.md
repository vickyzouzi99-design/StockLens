# 邀请码与线上账号

默认需要登录；邀请码为一次性激活凭证，注册后使用用户名与密码登录。SQLite 保存账号、哈希密码、哈希会话、邀请码哈希、每日额度使用情况和每个用户的策略库。所有写入使用事务，策略采用 revision 乐观锁，拒绝跨页面旧版本覆盖。账号间策略不可见，密钥仍只在服务器。

## 管理员发邀请码

在服务器上加载与 API 相同的环境变量后执行：

```powershell
.\.venv\Scripts\python.exe backend\accounts.py --daily-limit 10 --days 7
```

命令仅显示一次生成的邀请码，请私下发给用户，不要提交仓库或截图公开。默认数据库为 `data/accounts.sqlite3`；部署必须将 `STOCKLENS_ACCOUNT_DB` 指向持久化路径，做好文件权限与备份。不要向用户开放该管理命令。

## 费用边界

- 每个邀请码决定该账号的每日 AI 调用次数（默认10）；`STOCKLENS_GLOBAL_DAILY_LIMIT` 默认200，为全站上限。
- 日期按 GMT+8。调用前使用 SQLite 写事务预占一次额度，包含失败和超时，不自动退还，避免重试绕过费用上限。两个模型共用额度。
- 模型输出最多2048 tokens；用户输入最多500字。调用次数是成本控制措施，不是精确货币账单。
- 载入策略、编辑阈值、保存策略和数据筛选不调用 AI。
- 登录尝试按来源地址限制，15分钟最多30次。反向代理应正确设置真实客户端地址；不要将不受信任的转发头直接透传。

## 部署

生产必须配置 `STOCKLENS_ENV=production`、HTTPS、同源前端和 API。会话为 HttpOnly、SameSite=Lax、7天过期；生产使用 Secure cookie。生产模式下不能用 local 配置绕过登录。退出会话后服务端立即删除对应 token。服务只在127.0.0.1监听，由反向代理对外提供HTTPS；端口与数据库不直接暴露公网。

仅在离线本机开发时可显式设置 `STOCKLENS_ACCESS_MODE=local`，保留旧浏览器策略模式。账号模式不会自动读取其他人在共享浏览器留下的策略；用户可明确选择导入旧策略，原始 localStorage 不删除。

首版尚未提供忘记密码、管理员网页、按账号撤销界面或邮件验证。线上运营前需确定人工账号恢复流程。此功能不等于已部署到服务器。
