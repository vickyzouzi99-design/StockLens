# 服务器部署与验收

状态：配置已准备，尚未在服务器安装或启用。适用单台 Linux + systemd，目录沿用 `/opt/stocklens`，持久数据目录 `/var/lib/stocklens`。实际系统、域名和访问方式确定后再执行部署。

## 服务结构

浏览器 → Caddy（HTTPS、前端静态文件、`/api/*` 反向代理）→ 本机 FastAPI `127.0.0.1:8000`。
独立 `stocklens-refresh` worker 写入持久数据目录，API 从同一目录读取。
前端生产构建默认请求同域 `/api`，开发环境默认请求 `127.0.0.1:8000`。无需将开发地址写入线上构建。

模板：

- `deploy/stocklens-api.service`：API 自启动与异常重启。
- `deploy/stocklens-refresh.service`：独立四时点采集进程。
- `deploy/api.env.example`：OpenAI / DeepSeek 配置，两家密钥独立。
- `deploy/refresh.env.example`：扶摇数据配置。
- `deploy/Caddyfile.example`：同域前端与 API、HTTPS。

## 准备应用

将 `backend/`、`frontend/`、`deploy/` 和文档传到 `/opt/stocklens`。不复制本地 `.env`、Windows `.venv` 或 `node_modules`。以下命令只用于目标服务器；不会在 Windows 上执行。

1. 安装 Python 3.10+、支持项目锁文件中 Vite 版本的 Node.js（本地验证为 Node 26）、Caddy；创建 `stocklens` 服务账户，并保证 Caddy 能读取前端构建目录。
2. 创建持久目录和配置目录：

```sh
sudo install -d -o stocklens -g stocklens /var/lib/stocklens
sudo install -d -o stocklens -g stocklens -m 700 /etc/stocklens
python3 -m venv /opt/stocklens/.venv
/opt/stocklens/.venv/bin/pip install -r /opt/stocklens/backend/requirements.txt
cd /opt/stocklens/frontend
npm ci
npm run build
```

3. 参考 env 示例创建 `/etc/stocklens/api.env` 和 `refresh.env`，填入各自密钥。权限600，所有者 `stocklens`，不写入源码或前端环境变量。API 示例模型可改为已获授权的模型。
4. 两个服务的 `STOCKLENS_DATA_DIR` 保持一致。不要设置指向旧5只快照的 `STOCKLENS_SNAPSHOT`。
5. 首次启动前，将本地已验证的 `data/stock_snapshot_latest.json` 与对应的 `data/history/<snapshot_id>.json` 放入 `/var/lib/stocklens` 的相同结构，并归属 `stocklens`；或先在服务器执行一次完整采集。仅启动时点调度，在下个到期交易时点前不会产生初始快照。

服务设置 `STOCKLENS_ENV=production`：API / 解析器以服务环境变量为优先。本地开发保留项目 `.env` 优先，避免开发工具注入的同名配置覆盖项目凭据。采集器始终保留进程环境优先。

## 安装与启动

先将 Caddy 模板中的 `stocklens.example.com` 替换为实际域名，确认 DNS 指向服务器、80/443 可访问。Caddy 的配置只将 `frontend/dist` 暴露为静态目录；`/api` 前缀传给 FastAPI 时保留。

```sh
sudo cp /opt/stocklens/deploy/stocklens-api.service /etc/systemd/system/
sudo cp /opt/stocklens/deploy/stocklens-refresh.service /etc/systemd/system/
sudo systemd-analyze verify /etc/systemd/system/stocklens-api.service /etc/systemd/system/stocklens-refresh.service
sudo systemctl daemon-reload
sudo systemctl enable --now stocklens-api.service stocklens-refresh.service
```

将改好域名的 Caddy 配置安装到 `/etc/caddy/Caddyfile`（若服务器已有站点，合并站点块，不覆盖其他站点），然后：

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl enable --now caddy
sudo systemctl reload caddy
```

同域部署不需要跨域来源，示例 `STOCKLENS_CORS_ORIGINS` 为空。只有前后端分开部署时，才填入明确的前端来源；多个来源用逗号分隔。前端 `VITE_API_BASE_URL` 必须在构建时设置，不能依赖服务器运行时替换。

## 验收

```sh
curl --fail http://127.0.0.1:8000/api/health
curl --fail https://实际域名/api/data/status
sudo systemctl status stocklens-api.service stocklens-refresh.service caddy
sudo journalctl -u stocklens-refresh.service -n 100 --no-pager
```

浏览器验证：输入自然语言、确认条件、执行筛选、打开股票详情；调整阈值时快照 ID 保持一致；主动选择最新数据时建立新的比较起点。
观察交易日北京时间 09:30、11:30、13:00、15:00 的调度与发布记录；重启 worker 后同一成功时点不重复采集。失败应保留旧快照并等待10分钟后重试。
代码已用模拟时间验证四时点和持久化恢复；真实 Linux 服务权限、HTTPS、浏览器布局和跨时段运行仍需在目标环境验收。

历史快照当前不会自动清理；删除历史会使引用该快照的会话返回409，页面需主动切换最新数据。部署时保留可供研究对比的历史文件，并安排持久目录备份。

配置参考：[Caddy 静态站点与 API 模式](https://caddyserver.com/docs/caddyfile/patterns)、[systemd 执行环境与目录配置](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)。
