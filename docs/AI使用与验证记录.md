# AI 使用与验证记录

## 使用了什么

| 工具 | 参与环节 | 边界 |
| --- | --- | --- |
| Codex 编码助手 | 阅读真实代码、实现交互与接口、补测试、定位错误、整理交付 | 生成代码须经测试，不能把计划当成已完成功能 |
| OpenAI / DeepSeek API | 产品运行时的意图提取、澄清、可选指标补充 | 默认模型配置为 gpt-4o-mini / deepseek-flash；不生成金融数据或买卖建议 |
| Playwright、单元测试、Git | 浏览器验收、回归和版本记录 | 是验证与工程工具，不是 AI，也不能单凭构建通过证明业务正确 |

## 人工决策与纠错

用户确定普通投资者的产品定位、三步流程、指标边界、行业多选、策略复用、邀请码与费用控制。以下问题由用户反馈或实测暴露，Codex据此定位实施，而非模型自行验收：

| 问题 / 不合理结果 | 修正及验证 |
| --- | --- |
| “潜力股”“风险低”直接报错或被擅自映射 | 先澄清含义；缺失阈值留空，不能以低波动代替全部风险 |
| 负 PE 提示离输入框太远 | 行内错误与提交保护；保存失败也显示具体原因 |
| 模型遗漏银行等限制 | 必填契约、目录校验与遗漏阻断；扩展真实用例修复后通过 |
| AI 只像参数填表 | 同次解析可附最多两项补充指标，解释理由和局限；不自动启用、不生成额外阈值 |
| 两个 API 均连接失败 | 查明后端启动于受限沙箱，Windows 10013；获授权联网环境重启后，从实际 HTTP 接口验证两家成功 |
| 策略只保存执行参数、丢失停用值 | 保存完整快照、版本迁移、显式更新与另存；恢复不请求 AI |
| 行业面板没有明确结束操作 | 增加完成选择、外部点击和 Escape 收起；六行业保存、刷新恢复、更新通过真实界面验证 |
| 追踪 ID 对普通用户无帮助 | 默认显示数据来源、报告期、时间与计算输入，技术 ID 折叠用于反馈 |
| 首屏、编辑态和登录滚动体验不一致 | 共享高度规则、取消修改恢复原需求、宣传区居中并避让页脚；浏览器验证短窗口与手机 |
| 生产默认服务与结果首屏不符合演示需要 | 前后端均默认DeepSeek、保持禁止自动回退；执行后默认符合列表，零结果明确提示；离线及浏览器验收，无额外模型调用 |

## 已执行的真实验证

- 历史运行中的 HTTP 语义验收：OpenAI / DeepSeek 各8项，共16/16通过。覆盖口语数字、缺失阈值、OR、行业排除、中文矛盾、营收与利润区分、模糊风险及补充定义。
- 此前行业与财务扩展用例修复后，两家各6/6。保留历史结果，不冒充当前每次都重跑。
- 已完成“PE≤30、利润增长≥10%，建议其他指标”验收：两家各调用一次，均保留原条件并给出两项可选补充。点击加入无新增模型请求，未自动填写阈值。
- 浏览器用真实后端、真实金融快照和隔离测试账号验证。规则和布局修复优先使用不收费场景，不反复请求模型节省用量。

测试详情与可复现命令见[测试说明](测试说明.md)。原始运行记录、截图、测试凭证放在被忽略的 artifacts，不提交公开仓库。没有使用 AI 合成的股票数据、评分、收益或虚构溯源充当验收。
