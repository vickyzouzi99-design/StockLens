# AI 使用与人工纠错记录

## 产品中的 AI

OpenAI / DeepSeek 负责把用户描述提取为结构化筛选条件、待补充数值、模糊目标和不支持要求。用户选择服务，不自动切换。股票数据由扶摇采集，筛选由确定性规则引擎执行。恢复已保存策略、修改阈值和再次筛选均不请求 AI。

密钥只存在服务端环境变量或本地 `.env`，不会写入浏览器策略、前端包或仓库。日志与验收报告不记录授权请求头。

## 开发中的 AI 与用户决策

Codex 辅助阅读交接材料、检查代码、实现功能、编写测试和交付文档。用户确定产品定位、交互方案、模型选择、股票池规模、更新时间和策略管理流程。代码生成后经过离线回归和真实接口验证；没有把模型生成的说明当作数据事实。

| 反馈或验证发现 | 纠正措施 | 验证依据 |
| --- | --- | --- |
| 负 PE 输入提示距离字段过远 | 字段附近显示校验提示，提交时聚焦无效项 | 前端 validation 测试 |
| “潜力股”被当作不可执行报错 | 引导用户明确关注方向，缺失阈值留空 | guidance 测试、真实语义验收 |
| 产品不是替用户推荐股票 | 改为偏好、指标、用户确认及逐项核验流程 | 用户确认的 persona 与产品原则 |
| OpenAI 漏掉银行行业条件 | 补全必填 JSON 字段，增加遗漏阻断 | 新增六场景修复后通过 |
| 两个 API 在网页中都报连接失败 | 查明受限沙箱后端 Windows 10013；在获授权的联网环境重启 | 运行中 HTTP 接口两个服务均返回 200 |
| 策略保存仅覆盖已执行参数 | 保存完整条件快照、停用阈值、启用状态；独立抽屉管理，第二步也能保存 | 策略迁移、快照及非法条件测试 |
| 时间标注过长 | 使用 Asia/Shanghai 显示并标注 GMT+8 | 源码及构建检查 |

## 仍需保持的边界

自然语言模型仍可能漏提取或误解需求，用户必须核对条件。正则校验只覆盖明确数值表达，不能保证识别全部语义矛盾。当前执行逻辑为 AND、固定方向阈值和单一同花顺行业，不支持 OR、NOT、区间、收益保证或未来预测。不得将一次测试通过解释为任意措辞都能正确理解。
